# 与原项目的差异

Claude CoastClear（App 名 `cc`）基于原项目 4.18 源码独立开发。本文集中说明它与原项目长期存在的差异，随功能变化持续维护；某个版本具体改了什么见 [CHANGELOG.md](../CHANGELOG.md)。

## 名称与路径

- 项目名为 Claude CoastClear，GitHub 仓库名为 `claude-coastclear`。
- 应用、可执行文件、界面文字统一为 `cc`，macOS Bundle ID 为 `local.cc`，构建产物为 `menubar/cc.app`。
- 检测脚本为 `cc-network.sh`（三路出口与线路检测）、`cc-check.sh`（完整体检与修复）、`cc-consent.sh`（确认与授权）。
- macOS 数据目录为 `~/Library/Application Support/cc`，可用 `CC_DATA_DIR` 指定其他目录。
- 不读取、不迁移、不修改原项目的数据目录和登录启动项。
- 使用独立版本号，记录在根目录 `VERSION`，从 1.0.0 开始。

## 默认行为

- 启动、定时检测、手动检测和退出都只检测，不修改系统时区、DNS、PAC、区域格式、其他应用配置或登录启动项。检测只在 cc 自己的数据目录写入报告、缓存和日志。
- 时区不再自动跟随出口；不匹配时只给出建议。
- `install.sh` 默认不启动 App、不注册登录启动；只有显式 `--autostart` 才注册用户级登录启动。退出 App 只结束自身。

## 修复与权限

- 每次修复前列出将要修改的项目，确认后才执行；确认只对本次有效，不会开启以后的自动修复。
- 需要管理员权限时，确认后再弹出 macOS 原生授权；不配置免密 sudo，不安装 root 守护进程。
- 命令行修复同样要求确认，无交互输入时默认取消；显式 `--yes` 表示同意本次修改。
- DNS 修复只写入 1.1.1.1，接受代理 fake-IP（198.18/198.19）的解析结果，并在修改前备份原设置。

## 检测与显示

- 三路出口的本轮结果与历史稳定结果分开显示：失败的线路显示未获取，任意两路不同立即显示分流，检测未完成或过期不按一致计分。
- 国内侧固定使用一个探针站点，不回退到可能走不同路径的备用站点。
- 「重新体检」会等待并取得一次新的出口结果；地区未确认时显示「地区待确认」或「地区复核中」。
- 评分暂时失败时保留上次分数，空闲时自动补测一次。
- IPv6 出口会实际探测，并区分本机直连、代理侧地址、无 IPv6 和探测未完成；菜单和报告页显示地址、归属与来源，归属查询使用 HTTPS。

## 移除的功能

- 在线更新检查、升级提示和自动下载安装。
- Codex 本地代理、请求状态缓存及相关配置接入。
- Linux 实现、测试和打包脚本。
- Windows 托盘版本（不在本仓库中，暂不维护）。
- root 守护进程、免密修复安装脚本，以及旧数据目录的自动迁移。

## 平台范围

- 只维护 macOS（12 及以上，arm64 与 x86_64）。
